# Research: official CLIs, agent skills, pnpm supply-chain settings

Date: 2026-11-11. Sources were read live (pnpm.io docs repo, vendor docs, npm registry, GitHub). Every claim has a URL; **[unconfirmed]** marks what could not be verified, **[inference]** marks my own conclusion.

Versions below are npm `latest` dist-tags read from `https://registry.npmjs.org/<pkg>` on 2026-11-11.

## 1. pnpm

**Installed: `pnpm --version` → `11.25.0`** (published 2026-08-29). The binary is a Corepack shim: `~/.nvm/versions/node/v25.9.0/bin/pnpm -> ../lib/node_modules/corepack/dist/pnpm.js`; Node is v25.9.0.

Context that matters:
- npm `latest` for pnpm is now **12.18.0** (the Rust port); the newest 11.x is `latest-11` = **11.28.9** (2026-10-27). Source: https://registry.npmjs.org/pnpm. A bare `pnpm self-update` jumps to 12; use `pnpm self-update 11` to stay on 11. Source: https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-11.x/installation.md
- **pnpm.io now documents v12.** The v11 docs live in the docs repo at `versioned_docs/version-11.x/` (https://github.com/pnpm/pnpm.io/tree/main/versioned_docs/version-11.x). Everything below is from those files.
- The v11 docs cover up to 11.28, so a few documented features are newer than the installed 11.25.0 (flagged as such below).

### File rule in pnpm 11

"Only auth, registry, TLS, proxy, and `local-address` settings are read from `.npmrc` files. All other settings are configured in `pnpm-workspace.yaml` or the global `config.yaml`." pnpm 11 also no longer reads the `pnpm` field of `package.json`. Sources: https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-11.x/settings.md, https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-11.x/migration.md

### What changed between pnpm 10 and 11

Source for v10 values: https://github.com/pnpm/pnpm.io/blob/main/versioned_docs/version-10.x/settings.md; for the changes: migration.md.

| Item | pnpm 10 | pnpm 11 |
|---|---|---|
| Where settings live | `.npmrc` (kebab-case) and `package.json#pnpm` | `pnpm-workspace.yaml` (camelCase); `.npmrc` only auth/registry/TLS/proxy; `package.json#pnpm` ignored |
| `minimumReleaseAge` default | `0` | `1440` |
| `strictDepBuilds` default | `false` | `true` |
| `blockExoticSubdeps` default | `false` | `true` |
| `verifyDepsBeforeRun` default | `false` | `install` |
| Build allow-list | `onlyBuiltDependencies`, `neverBuiltDependencies`, `ignoredBuiltDependencies`, `onlyBuiltDependenciesFile` | **removed**, replaced by `allowBuilds` |
| pnpm version management | `managePackageManagerVersions`, `packageManagerStrict`, `packageManagerStrictVersion`, `COREPACK_ENABLE_STRICT` | **removed**, replaced by `pmOnFail`; new `devEngines.packageManager` |
| Audit ignore | `auditConfig.ignoreCves` | `auditConfig.ignoreGhsas`, then `audit.ignore` (11.16) |
| New in 11 | — | `minimumReleaseAgeStrict`, `minimumReleaseAgeIgnoreMissingTime`, `registries`, `trustLockfile` (11.3), `pnpm audit signatures` (11.1) |
| Env vars | `npm_config_*` read | only `pnpm_config_*` |
| CI install | docs used Corepack | docs now use the standalone installer or `pnpm/setup` action; Corepack described as slower shim |

Migration codemod: `pnpx codemod run pnpm-v10-to-v11` (migration.md). Note: third-party docs still use pnpm 10 names, e.g. Lefthook tells you to add `lefthook` to `onlyBuiltDependencies` (https://lefthook.dev/installation/node/); on pnpm 11 that becomes `allowBuilds: { lefthook: true }`.

Documented but **newer than installed 11.25.0** (unavailable until an upgrade): `trustPolicyExcludePrune` (11.27), audit ignored-advisory reporting (11.26), side-effects-cache flag changes (11.26). Upgrading to 11.28.9 vs pinning 11.25.0 is an owner decision.

GitHub Actions: docs use `pnpm/setup@fa36a5ef7dcdefc3a7cb25655c122e00cf6e636e # v3.1.2` (SHA-pinned), which reads the version from `packageManager`/`devEngines.packageManager` (continuous-integration.md).

## 2. shadcn/ui

CLI `shadcn` **4.23.0** (2026-10-27).

- **Init (Vite + React + TS + Tailwind):** scaffold a new app with `pnpm dlx shadcn@latest init -t vite`; or in an existing `pnpm create vite@latest` app add Tailwind (`pnpm add tailwindcss @tailwindcss/vite`, `@import "tailwindcss";` in `src/index.css`), the `@/*` alias in `tsconfig.json` + `tsconfig.app.json`, `@types/node`, `vite.config.ts` with `react()` + `tailwindcss()` and `resolve.alias`, then `pnpm dlx shadcn@latest init`; add components with `pnpm dlx shadcn@latest add button`. https://ui.shadcn.com/docs/installation/vite
- **Init options worth deciding:** `-b, --base base|radix|aria` (Base UI, Radix or React Aria primitives), `-p, --preset`, `--css-variables` (default on), `--rtl`, `--pointer`. https://ui.shadcn.com/docs/cli
- **Tailwind:** new projects start on **Tailwind v4** and React 19; v3 projects still work. `tailwindcss-animate` is deprecated in favour of `tw-animate-css`. https://ui.shadcn.com/docs/tailwind-v4
- **Theming tokens:** CSS variables under `:root` and `.dark`, OKLCH values (`--primary: oklch(0.205 0 0)`), mapped to utilities in `@theme inline { --color-primary: var(--primary); }`; `X` / `X-foreground` pairs; one `--radius` drives the radius scale. New token = define in `:root`/`.dark` → expose in `@theme inline` → use `bg-warning`. `tailwind.cssVariables` in `components.json` defaults to `true` and is an install-time choice; `baseColor` options: Neutral, Stone, Zinc, Mauve, Olive, Mist, Taupe. https://ui.shadcn.com/docs/theming. **[inference]** For a single dark theme, put the dark values in `:root` (or always set `.dark`).
- **Charts:** `pnpm dlx shadcn@latest add chart`; uses **Recharts v3** (recharts latest 3.10.1); colours via `ChartConfig` → `var(--color-KEY)` and `--chart-N` tokens (page shows `--chart-1`/`--chart-2`; `--chart-3..5` **[unconfirmed on that page]**). https://ui.shadcn.com/docs/components/chart
- **Agent skill (official):** `pnpm dlx skills add shadcn/ui`. It runs `shadcn info --json` for project context and covers the CLI, theming, registries, MCP and composition rules. https://ui.shadcn.com/docs/skills. The skill source is `skills/` in https://github.com/shadcn-ui/ui (directory exists). The `skills` installer is Vercel's open tool (https://github.com/vercel-labs/skills, npm `skills` 1.8.1). **[inference]** On pnpm, pin it: `pnpm dlx skills@1.8.1 add …`.
- **MCP (official):** `pnpm dlx shadcn@latest mcp init --client claude`; documented `.mcp.json`: `{"mcpServers":{"shadcn":{"command":"npx","args":["shadcn@latest","mcp"]}}}`. It browses, searches and installs from any shadcn-compatible registry; extra registries go in `components.json`. https://ui.shadcn.com/docs/mcp. **[inference]** The `npx …@latest` form bypasses pnpm's release-age policy. Pin the version or use a local dev dependency.

## 4. Firebase Spark plan

Source: https://firebase.google.com/pricing

- **Cloud Functions:** "Not applicable" on Spark, so Blaze is required.
- **Cloud Storage:** "Not applicable" on Spark. Since **2026-02-03** a default bucket requires Blaze, and Spark projects lose read/write and console access to all buckets, including existing `*.appspot.com` ones (data kept, inaccessible). https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024. This matches the project rule: free-exercise-db photos ship as Hosting assets.
- **Firestore (Standard edition), free:** 1 GiB stored, 50K reads/day, 20K writes/day, 20K deletes/day, 10 GiB/month egress.
- **Hosting:** 10 GB storage, 360 MB/day transfer. **[inference]** The 800+ exercises × 2 photos of free-exercise-db must fit under 10 GB, and image traffic counts against 360 MB/day; measure the asset size at plan stage.
- **Auth (with Identity Platform):** 50K MAU; SAML/OIDC 50 MAU; phone/SMS auth not available on Spark.
